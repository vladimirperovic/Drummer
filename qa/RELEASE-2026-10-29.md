# Public release verification — 29 October 2026

This release adds MusicXML reading, notation scaling, visible timing feedback, end-of-session notation reports, English-by-default, public documentation and GitHub Pages deployment.

## Local verification

- **229 JavaScript model tests passed.** This includes early-hit retention, audio cancellation, report timing, swing and redundant MIDI meter metadata.
- **7 Python tests passed.**
- **137 existing Chromium browser scenarios passed.** Some were rerun individually after an intentional UI behavior change or a transient browser network failure; passing final assertions were retained.
- **19 new Chromium scenarios passed:** note layout 4, timing report 3, feedback/editor/draft 5, MusicXML 6 and language default/persistence 1.
- Total: **392 distinct test cases**. Focused reruns and the packaged-build smoke check are additional executions.
- The built `dist/` artifact was served separately and passed the default-English/Serbian persistence smoke check.
- MusicXML was tested on the `/Drummer/` subpath and offline, with plain XML, compressed MXL, standard DTD declarations, rejection of external resources and malformed/oversized archives.
- Desktop and phone screenshots were visually inspected. Public screenshots contain project-generated examples.

The pre-publication code review found and fixed: first early hits discarded, editor cells unlocked after navigation during playback, lost draft warning after reload, redundant MIDI meter rejection, choke affecting a future voice, and a stale kit load overwriting a newer choice. The full-surface 2D flash rectangle was replaced with bounded pad geometry; GPU-specific intermittent flashing could not be directly reproduced.

The regression suite uses simulated MIDI, controlled timestamps and software WebGL. It does not certify physical Roland hardware, audible latency or every GPU. MusicXML is a reading view, not pitched-instrument grading. Live GitHub Actions results are available from the repository's Actions tab.
